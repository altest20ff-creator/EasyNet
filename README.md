# EasyNet Prototype (Arabic RTL)

نسخة أولية عملية لمنصة **EasyNet** لإعداد أجهزة الشبكات خطوة بخطوة (تجريبية وقابلة للتوسعة).

## التشغيل محلياً

```bash
cd /home/runner/work/EasyNet/EasyNet
npm test
npm run lint
npm run build
npm start
```

ثم افتح:

- http://localhost:4173

## ما الذي يقدمه هذا النموذج؟

- واجهة عربية RTL متجاوبة للهواتف وسطح المكتب.
- تدفق اختيار متدرج: **نوع الجهاز → الشركة المصنعة → الموديل**.
- لا تظهر لوحة الإعدادات قبل اختيار الموديل.
- لوحة إعداد مخصصة حسب قدرات الموديل (إخفاء الخيارات غير المدعومة).
- خطوات الإعداد: معلومات الجهاز، وضع التشغيل، WAN/LAN، Wi‑Fi/SSID، الأمان، القناة وقوة الإرسال، المراجعة النهائية.
- تحقق من المدخلات ورسائل خطأ واضحة.
- ملخص نهائي مع **نسخ** و**تنزيل JSON**.
- قسم مقالات/دروس + مساحة إعلانات تجريبية منفصلة عن تجربة الإعداد.
- رسائل أمان وخصوصية واضحة (عدم إدخال كلمة مرور الإدارة، وعدم التخزين).
- دعم الوضع الداكن.

## بنية البيانات (قابلة للتوسعة)

البيانات موجودة في:

- `/home/runner/work/EasyNet/EasyNet/data/devices.js`

كل موديل يحتوي مصفوفة دعم صريحة داخل `supported` مثل:

- `operationModes`
- `wan`, `lan`, `wifi`
- `wifiBands`, `securityModes`
- `channels`, `txPowers`

### موديل متضمن حسب الطلب

- **Ruijie / Reyee → RG-RAP6262 Outdoor**

## إضافة شركة أو موديل جديد

1. افتح `data/devices.js`.
2. أضف الشركة داخل `manufacturers` لنوع الجهاز المناسب.
3. أضف الموديل داخل `models` مع حقل `supported` كامل.
4. شغّل الاختبارات:

```bash
npm test
```

> الواجهة تقرأ البيانات ديناميكياً، لذلك أي موديل جديد يظهر تلقائياً في القوائم.

## ما هو تجريبي مقابل ما يحتاج تكامل فعلي؟

### تجريبي في هذه النسخة

- تجربة المستخدم كاملة من الاختيار حتى المراجعة.
- توليد/نسخ/تنزيل ملخص الإعدادات.

### يحتاج تكامل فعلي لاحقاً

- الاتصال المباشر بالأجهزة عبر APIs أو SSH أو SDKs.
- تطبيق الإعدادات فعلياً على الراوتر/نقطة الوصول.
- إدارة حسابات ومصادقة وتخزين آمن على الخادم.
